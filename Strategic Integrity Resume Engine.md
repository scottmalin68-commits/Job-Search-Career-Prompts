### PURPOSE
This prompt turns a master skills/resume file + a target job description into a high-signal, de-risked, ATS-friendly resume and cover letter.  

It forces the AI to:
1. Identify the real business/technical pain the role exists to solve.
2. Translate the candidate’s actual history into the language and principles of the job (not just keyword stuffing).
3. Surface the strongest “Hidden Gem” proof points while actively killing generic responsibility language.
4. Produce recruiter- and bot-ready materials that maximize both human impact and passive discovery.

Use this when you need a tailored application package that is honest, metric-driven, and optimized for both human recruiters and AI screening systems.

### PHASE 1: THE DE-RISKING AUDIT
Before writing anything, perform a “Strategic Audit” in plain text:

1. **The Real Problem:** What literal technical or business pain is this role meant to solve?
2. **Functional Translation:** Map the candidate’s history to the JD’s core principles (e.g., “Automation-First,” “Risk Governance,” “Zero Trust”) regardless of specific tool names.
3. **The Risk Profile:** Identify why a recruiter or hiring manager might hesitate (e.g., “too senior,” “legacy background,” “title mismatch”) and state the “crush” strategy.
4. **The Language Mirror:** Identify 3–5 high-value technical terms or phrases from the JD that must appear naturally.
5. **The Sinker:** The single strongest metric or achievement that proves this candidate is the “Hidden Gem.”

---

### PHASE 2: MANDATORY OUTPUT ORDER
1. **Header:** [NAME & CREDENTIALS]. Use ( • ) separators.
2. **Professional Summary:** Humanized “I” voice. Focus on skill velocity and clear career trajectory.
3. **AREAS OF EXPERTISE:** Single paragraph block; items separated by bold middle dot (**·**).
4. **Key Accomplishments:** Exactly 3 bullets. Enforce the 1:1 Metric Rule (one clear metric or outcome per bullet).
5. **Professional Experience:** Job / Company / Dates as plain text; bullets in a single code block.
6. **Early Career / Education / Technical Competencies / Certifications.**

---

### PHASE 3: THE GOD MODE WRITING RULES
- **Signal-to-Noise Filter:** Delete any bullet that is a generic responsibility. Every bullet must be a Capability Signal (e.g., “Reduced X by Y using Z”).
- **The Evidence Test:** If the JD asks for a modern tool and the source shows a legacy equivalent, emphasize the architecture, logic, and outcomes that transfer.
- **Active Kill-Switch:** No passive language. Prefer: Orchestrated, Overhauled, Captured, Engineered, Drove, Delivered.
- **Eye-Tracking:** **Bold the win**, not the task.
- **Formatting:** Strict use of middle dot (·) bullets. No blank lines inside lists. Keep the entire experience section inside one code block for clean copy-paste.

---

### PHASE 4: THE INSIDER COVER LETTER
- **The Direct Lead:** Open with a direct claim of solving the “Real Problem” identified in Phase 1.
- **The Proof Paragraph:** One specific, high-signal win + technical proof. Hard 250-word cap.
- Keep tone professional, confident, and concise.

---

### PHASE 5: SEARCHABILITY & SIGNAL AUDIT (AI OPTIMIZATION)
1. **The Skills Graph:** List 3 keywords or signals missing from the source that should be added to LinkedIn to improve passive discovery for this tech stack.
2. **The Hidden Gem Flag:** Identify which GitHub project or contribution (from the SOURCE URL) most effectively demonstrates skill velocity to an AI recruiter.
3. **Bot-Ready Q&A:** Generate 2 technical branching questions a screening chatbot is likely to ask, plus high-signal answers.
