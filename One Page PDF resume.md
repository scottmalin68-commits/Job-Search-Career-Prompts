### PHASE 0: IDENTITY & ENGINE PRIMING (PRE-FLIGHT GATE)
1. Inputs  
Required: (1) Full Target Job Posting Snapshot (or raw JD), (2) [Candidate Name] - Template.docx.  
Optional: (3) Universal Job Fit Evaluation v1.8.0 packet. If omitted, proceed without a role-fit score and never invent one.

2. Fit Decision Consumption Gate (run before any generation):  
   - If imported Decision is SKIP, or any Hard Gate Fired is present: STOP ALL GENERATION. Output only the imported Decision, each fired gate with its evidence, and one line stating that no packet will be produced.  
   - If imported Decision is STRETCH: continue. Label the packet a stretch draft, not submission-ready.  
   - If imported Decision is APPLY or TAILOR: continue under existing rules.  
   - ATS Gap List items may be used only through the Missing JD Technology Protocol. Never write a missing vendor name into the content.  
   - If no 1.8.0 packet is attached: do not calculate or emit any fit score.

3. Base Source: Use [Candidate Name] - Template.docx (pages 1-2 content only) as the sole source of facts, tools, and metrics.

4. Pre-Flight Metrics Check: If fewer than 3 high-impact accomplishments have hard metrics matching the target, STOP ALL GENERATION. Output only a direct list of questions prompting the user for missing numbers.

5. Execution Mode: If gates pass, skip introductions. Start with the Phase 0.5 Spellcheck Log.

6. User Identity & Contact:  
   [Candidate Name], [Primary Certification]  
   [City, State Zip] | [Phone Number] | [Email Address] | [Citizenship / Work Auth]  
   [LinkedIn URL] | [GitHub URL] | [Key Metric / Contribution Count]

7. Title Line: Set to the posting title or a short human-readable version of it. Default: [Target Role Title].

8. Cover Letter: Plain text only. Generate a complete header block with date, company name, and address (use snapshot address or [COMPANY HQ ADDRESS]).

9. GitHub Placement: Keep on the header if applicable. Include technical contribution counts in the summary only when the target values automation or public work. Do not force it into the cover letter.

### PHASE 0.5: THE COLD-EYE SPELLCHECK
1. Brand Accuracy: Ensure correct casing for all technical vendors, platforms, and tool names present in the source template (e.g., cloud services, EDR tools, security platforms, scripting languages).  
2. Output: Render === SPELLCHECK LOG === at the top of the response.

### PHASE 1: TARGET ALIGNMENT
1. Snapshot Forensics: Identify the operational pain points and technical priorities the human reader will care about in the first six seconds.  
2. Semantic Clustering: Extract the highest-value keywords and outcomes from the snapshot. Prioritize must-have items.  
3. Keyword-Metric Anchoring: Pair real tools from the source with real outcomes from the source.  
4. Strict Provenance Mandate: Base every line on the source template. Do not invent tools, platforms, projects, certifications, metrics, duties, or dates.  
5. Missing Technology Protocol: Translate missing concepts using tools already in the source. Never output the missing vendor name.  
   - Lock required translation rules based on standard industry equivalents using only the candidate's actual toolset.  
6. Focus: Last 10 years of depth. Respect historical employment end dates as defined in the source template.  
7. Ranking: Order achievements by visual impact and direct proximity to the target priorities. Cap strictly at 4–5 high-impact items to protect single-page layout.

### PHASE 2: HUMAN-SCAN WRITING RULES
1. Proof Standard: Every line shows real work. No filler.  
2. Metric Mandate: Achievements use only lock-list numbers from the source. Bold the metric, not the verb. No invented percentages or headcount.  
3. Number Lock List (do not drift):  
   - Use only verified numbers, scale metrics, project counts, timelines, and certifications explicitly documented in the candidate's source template.
4. Vocabulary:  
   - BANNED: spearheaded, responsible for, passionate, motivated, team player, fast-paced, cutting-edge, key contributor, elegant, game-changing, dive into, “at the intersection of”, “proven ability”, “my career spans”.  
   - ALLOWED verbs: Led, Built, Owned, Designed, Tuned, Isolated, Cut, Wrote, Mentored.  
   - OPTIONAL: Orchestrated, Overhauled, Engineered, Remediated.  
5. Boldface: Bold only the quantitative outcome.  
6. Summary: 2 short lines max focused on craft and immediate impact. No year tallies.  
7. Education: Omit entirely.  
8. Certifications: Include only if the target explicitly values a cert that exists in the source. Otherwise omit.

### PHASE 2.1: CORE EXPERTISE
4–5 hyper-targeted, high-signal items. Lead with the tools and domains the human reader needs to see immediately. Source only.

### PHASE 2.2: TOOLS & TECHNOLOGIES
One dense pipe-separated line. Posting-relevant tools first. Source only. Exclude legacy artifacts not present in active source history.

### PHASE 2.3: SELECT ACHIEVEMENTS
4–5 short impact statements. Lead with the strongest visual wins matching the target. Start with an allowed verb. Bold the metric.

### PHASE 2.4: CERTIFICATIONS
Include only when the target specifically calls for one that is in the source. Otherwise omit the section.

### PHASE 3: COVER LETTER
Plain, direct, senior IC. Open with a solution hook tied to the primary pain point. 2–3 verified wins. No fluff. Plain text only.

### PHASE 4: STRATEGY & SCORECARD
1. SALARY STRATEGY: plain text.  
2. PACKET QUALITY SCORECARD: visual clarity | evidence density | human-scan readiness.  
3. FIT DECISION (IMPORTED): one line only (APPLY | TAILOR | STRETCH | SKIP | NOT PROVIDED). If STRETCH, append “Stretch draft — not submission-ready.”

### PHASE 5: PRE-STREAM VERIFICATION
1. Fit Decision gate ran first.  
2. Title set.  
3. Achievements use only lock-list metrics (capped at 4–5); bolds on results.  
4. All tools from source; missing items translated without forbidden vendor names.  
5. Education omitted.  
6. Certifications omitted unless explicitly warranted.  
7. Employment end dates match source template exactly.  
8. Output is structured blocks only, optimized for a single-page landscape visual PDF.

### PHASE 6: LANDSCAPE ONE-PAGE VISUAL PDF OUTPUT
1. Emit content blocks only. No Word document. No full reverse-chronological experience section.  
2. Required blocks for the visual layout:  
   - Header: name, short title, contact line, 2-line brand summary.  
   - Core Expertise: 4–5 short high-signal items.  
   - Select Achievements: 4–5 short impact statements with bolded metrics.  
   - Tools & Technologies: single dense pipe-separated line.  
   - Certifications: only if warranted; otherwise omit.  
   - Experience Highlights: lean two-line company/title/date entries for recent roles plus one line noting full detail lives in the traditional resume.  
3. Do not invent tools, metrics, or a photo.  
4. After the blocks add: “Content ready for landscape one-page visual PDF. Intended for direct human review (LinkedIn, email, networking). Not for ATS application upload.”  
5. Cover letter remains plain text.
